*2026-06-11. Build contracts for the first PRACTICE-PHILOSOPHY.md modalities:

## 1. One real sentence a day

The bridge from practice to life at minimum dose: one sentence the person will
actually say today, rehearsed together, asked about tomorrow. An OFFER, never
an obligation — a missed day produces no debt, no broken anything.

### Learner-context (extend `learner-context-service.js`, schema v3, additive)
```jsonc
voice.realSentences: [            // newest first, cap 60
  {
    "id": "rs_...",
    "text": "A flat white, please.",   // <= 120 chars
    "pickedAt": "2026-06-11",          // local date string
    "status": "picked" | "ready" | "carried" | "debriefed",
    "outcome": null | "said-well" | "said-rough" | "not-said",
    "note": ""                          // optional, <= 240 chars
  }
]
```
- Today's sentence = first entry with `pickedAt === today`.
- Pending debrief = newest entry with `status in (picked|ready|carried)` and
  `pickedAt < today` (only the most recent one is ever asked about).

### Kernel routes
- `GET  /voice/real-sentence?studentId=` → `{ today: entry|null,
  pendingDebrief: entry|null, suggestions: string[3] }`. Suggestions are
  deterministic: built from learner topics/hobbies + displayName ("Hi, I'm
  ⟨name⟩ — nice to meet you.") + a small everyday-template pool (coffee order,
  phone greeting, asking for help in a shop). Never repeats the last 10 picked.
- `POST /voice/real-sentence/pick { studentId, sessionId?, text }` → validates
  ≤120 chars, creates the entry AND a PracticeCard (`kind: 'real_sentence'`,
  focus = current session focus) set active for the session. Returns
  `{ entry, card }`.
- `POST /voice/real-sentence/outcome { studentId, id, outcome, note? }` →
  sets status `debriefed` + outcome. Side effects: `said-well` appends a
  whatWorked entry ("real sentence carried: ⟨text⟩"); `said-rough`/`not-said`
  write NO negative record anywhere — the coach line handles it warmly
  (template: rough → "rough reps in the world still count — that took nerve";
  not-said → "days slip — it's still yours when you want it").

### Readiness (deterministic, advisory only)
After a take on a `real_sentence` card: if ≥2 takes today on it AND the
held-ratio (tokens hit / scored tokens) ≥ 0.7 on the latest → status `ready`.
The coach line acknowledges in plain words ("that one's ready to go outside").
NEVER gate or warn against saying it before "ready" — readiness is
encouragement, not permission. `carried` is set only by the user (an "I said
it" affordance available the same day) or implied at debrief time.

### Greeting follow-up
Extend the greeting flow: when `pendingDebrief` exists, line2 asks about it
("Yesterday's sentence — 'A flat white, please.' Did it get its moment?").
Frontend renders three quiet buttons under the greeting: **Said it — went
well · Said it — rough · Didn't today**, plus an optional one-line note.
One tap → outcome route → coach's template response in the thread. No
follow-up nagging if dismissed; it simply doesn't ask again for that entry.

### PracticeCard extension
`kind?: 'drill' | 'real_sentence'` (default 'drill') on the card model +
store + normalizers. Card behavior is otherwise identical (tokens, marks,
replay).

## 2. The time-lapse mirror

The person's own recorded arc — the honest progress device. One pinned take a
week (guidance, not rule).

### DSP (services/voice-trainer)
- `POST /api/v1/voice/attempts/{attemptId}/pin { studentId, label? }` →
  copies the attempt WAV + its timeline + metrics snapshot to
  `milestones/{studentId}/{date}_{attemptId}.wav` + `.json`. Idempotent per
  attemptId. Cap 500 per student (evict oldest beyond cap). Works only for
  attempts whose audio is still in the retention ring — pin promotes it to
  permanent.
- `GET /api/v1/voice/milestones?studentId=` → `[{ id, date, label,
  attemptId, durationMs, metricsSummary: { meanPitchHz?, resonance?,
  heldRatio? } }]` (oldest first).
- `GET /api/v1/voice/milestones/{id}/audio` → audio/wav.
- `DELETE /api/v1/voice/milestones/{id}` (unpin).

### Kernel proxies
`POST /voice/attempt/:attemptId/pin`, `GET /voice/milestones`,
`GET /voice/milestone/:id/audio`, `DELETE /voice/milestone/:id` — mirror the
existing attempt-audio proxy pattern, studentId resolved as elsewhere.

### Pin suggestion (deterministic, quiet)
After a take finalizes: if the student has NO milestone in the last 7 days AND
this take is the session's best so far (held-ratio, then confidence as
tiebreak) → include `pinSuggestion: { attemptId }` in the session payload. The
frontend shows a small affordance on the take result ("keep this one as this
week's marker") — an offer; ignoring it costs nothing and it doesn't repeat
within the session.

### Frontend mirror view
A modest panel (entry: "Your arc" link near the compass). Lists milestones on
a simple time axis (date + optional label). Default comparison: earliest vs
latest; user may pick any two. Playback: take A then take B sequentially
through the replay machinery, each animating its own compass trail (muted
"then" color vs current "now" color, sequential not simultaneous). Copy is
honest and calm: "Same phrase not required — listen for the center of the
voice." Anniversary line (6/12 months since first milestone) is ONE human
sentence in the greeting, no visuals.

## 3. Strain guardian (backbone)

Deterministic protection now; the v3 model learns to speak it natively later.

### Kernel accumulator (runtime)
Per session track: `sessionStartedAt`, take count, and per-take strain
evidence from the DSP attempt artifact (use the existing reliability/risk
fields — the builder agent must verify the exact field names in the artifact
metrics and document them in code).
Rules (tunable constants in one place):
- **Ease-off**: strain evidence on ≥2 of the last 4 takes → one coach
  template line ("let's take the next one easier — sip of water, drop the
  volume") + `guardian: { level: 'ease' }` in the session payload.
- **Close**: strain on ≥4 takes total OR (session > 25 active minutes AND any
  strain in the last 3 takes) → coach closing template ("that's enough for
  today — pushing a tired voice trains the wrong thing. The last takes were
  good ones.") + `guardian: { level: 'close' }`. Controls are NEVER locked;
  the session-end affordance is highlighted. If the user keeps going, the
  guardian repeats once at most, then stays silent (said its piece — adult
  autonomy).
- Guardian lines come from templates (deterministic), inserted into the coach
  thread exactly like coach messages; they also append a compact
  `strainWatch: { recentFlags, sessionMinutes }` field to the coaching signal
  (signal-builder) so the live LLM can reference it naturally.

### Frontend
Quiet hint rendering for `guardian.level` ('ease' → a small line under the
card; 'close' → the same plus highlighting the existing end-session control).
No modals, no red, no alarm sounds.
